# 多插件、多版本仓库描述 v1（M2 候选）

本契约是可选的导入描述层，不替换旧技术索引，不重新打包已有 Release，也不授权执行 Python。
本分支的仓库描述仅登记已经存在的 Hello 1.0.0；多插件、多版本行为用合成清单测试，不能把测试版本当作已发布插件。
宿主端对应能力仍需使用支持 M2 的版本；提交本文件不等于部署宿主或完成整个 issue #152。

## 三个文件的职责

- [index.json](<../index.json>)：保持旧 schema，面向已有市场客户端，每个 ID 一个当前版本。
- 当前版本取未撤下、未撤销版本中的 SemVer 最大值；同一版本的正式版高于预发布版。旧索引只保留依赖也能在该单版本集合中精确满足的条目，不改写依赖、不替换为其他旧版本；完整可用历史继续保留在 repository.json。
- [repository.json](<../repository.json>)：新导入客户端可枚举一个仓库内多个插件及其多个不可变版本。
- [presentation.json](<../presentation.json>)：中文说明、风险与版本级审核声明；不能覆盖技术清单或授予权限。

独立的 [repository.schema.json](<../schemas/repository.schema.json>) 引用已有技术清单 schema，不给旧清单增加任何字段。
如下只说明形状，Manifest 必须替换为完整、有效且已发布的清单，不能把省略对象发布：

```typescript
{ SchemaVersion: 1, Plugins: [
  { Id: "community.example.plugin", Versions: [
    { Version: "1.0.0", Manifest: /* 完整技术清单 */ {} },
    { Version: "2.0.0", Manifest: /* 完整技术清单 */ {} }
  ] }
] }
```

## 不变条件与离线发布检查

1. 顶层、插件组、版本项均拒绝未知字段；SchemaVersion 必须为 1。
2. 插件组非空且 ID 唯一；版本列表非空，同一 ID 内版本唯一。外层 ID/version 必须与内嵌清单完全一致。
3. 整个描述不超过 2 MiB，全部插件合计不超过 1024 个候选，而不是每组分别放行 1024 个。
4. 清单保持现有 Release URL、SHA-256、入口程序集、API、目标框架、依赖、设置约束；描述层不能覆盖这些值。
5. 旧索引中的每条当前清单必须在描述中完整保留；不能只核对摘要却悄悄改下载地址、权限或入口。
6. 每个版本必须与其版本目录中的不可变清单对象一致；缺失或不一致使发布检查失败。
7. 重复 JSON 属性、前后空白身份、空摘要占位符、自依赖/重复依赖、描述内已知依赖环均拒绝。
8. 依赖可以位于另一个仓库，描述验证不假定它已安装；宿主安装预览另行检查实际安装版本是否满足要求。
9. 中文元数据可对应描述中的非当前版本，但仍必须绑定该版本的精确 SHA-256。没有描述时继续只接受旧索引中的包。

离线检查不会联网，不运行 DLL，也不把“摘要一致”称为“审核安全”：

```bash
python tools/validate_repository.py
python tools/validate_presentation.py
python -m unittest discover -s tools -p 'test_*.py'
```

CI 仍保留旧 schema、Release pins、ZIP 与 SDK 检查，只增加新的仓库描述检查。
当前技术发布 schema 仍为 .NET 8/API 1；宿主能解析其他目标框架不等于本仓库发布契约已扩展，也不等于执行兼容性矩阵已经完成。

## 宿主发现与来源固定

只接受公开 GitHub HTTPS 仓库根地址或 Release tag 地址，不接受账户密码、查询参数、片段、私有地址或非标准端口。

1. 先通过受限 GitHub API 将默认分支或明确的 tag 解析为真实 commit；tag 不得被同名分支替代。
2. 从该 commit 读取仓库描述与可选中文说明；请求体积、跳转和 tag 解引用深度都有上限。
3. 只有描述返回 404 才适配同一 commit 下的旧索引；格式错误、超限或其他下载失败不能冒充“旧仓库”。
4. 将候选列表绑定到调用者和过期时间，返回不透明发现 ID；前端选择不能自己拼装或替换服务器候选。
5. 任意外部仓库的自称“官方/已审核”都不是可信凭据，导入展示降为社区/未审核；不从同名插件继承徽章。

## 只读预览与确认

仓库导入、市场安装、高级 JSON 均先获得服务器预览，再确认同一个预览；没有预览不能直接新装。
预览展示精确版本/摘要、来源快照、声明的权限/配置/依赖、已装版本、兼容性阻断、禁用状态及执行风险。

- 预览不下载 ZIP、不写设置、不产生安装回执、不加载 DLL。此时摘要与归档验证只能标为“确认时验证”，不能显示已完成。
- 预览绑定调用者、完整清单、安装状态 revision、来源快照和有效期；缓存最多 64 项、总序列化载荷预算 8 MiB（不是 CLR 堆占用测量），有效期 10 分钟，失效后必须重新预览。
- 确认前重查安装状态、依赖与来源：分支/tag 移动、索引/说明变化、清单篡改、过期或其他调用者的预览均拒绝。
- 审核声明不是运行时隔离；高级 JSON 不接受用户追加的审核/运行时授权信息。撤销治理仍属 M4 后续工作。
- 同一已完成意图的幂等重试返回原回执，不因预览后来过期而重复下载或重复安装。

安装后业务能力默认禁用，旧的启用意图不能让重新安装的插件在热应用或重启时自动启用。
禁用设置经宿主既有配置授权流程持久化，并在候选被发布为可激活状态之前完成。

**禁用不等于不执行任何第三方代码**：进程内 .NET 加载、构造器、模块初始化或属性读取仍可能执行代码；只是跳过正常启用的业务初始化/路由。
用户仍必须信任来源。没有容器/进程沙箱保证，不能用“未启用”淡化风险。

## API 迁移

M2 宿主增加 source/discover 与 preview 接口。旧只读 source/resolve 可保留兼容；新装接口需要 previewId。
旧客户端直接调用新装接口会收到 plugin_preview_required，需要升级为先预览再确认，不能降级为免预览安装。
更新、回滚、卸载的既有回执语义保留；完整生命周期和迁移增强仍属 M3。
